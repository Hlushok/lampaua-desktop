# MPV Direct3D 11 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Плавне вбудоване 4К-відтворення у повній локальній Windows x64 LampaUa зі збереженням керування Lampa.

**Architecture:** Прямий D3D11 backend на нашій MPV-базі з одним upstream-патчем. Виділений render thread і обмежений пул GPU-текстур передають кадри через публічний Electron API, без CPU RGBA/WGL/ANGLE. Дешевий transport-gate передує довгій компіляції DLL; успіх native MPV без повного Desktop не закриває дефект.

**Tech Stack:** Electron 45.0.0, N-API / C++17 / MSVC, D3D11 / DXGI, libmpv client API 2.6, TypeScript, WebGPU, Python 3, pinned Linux cross-build.

**Spec:** `docs/superpowers/specs/2026-10-21-mpv-d3d11-render-design.md`

## Global Constraints

- Windows x64; Windows UA Player, Android, встановлений Desktop і його профіль, Lampac, JackTor та VPS не змінюються.
- База MPV `36bf3d529059a947d6700adefeab3b421e537c19`, FFmpeg `5d4755f7dd03d84f006d5a0ef7e3c114f52b3d77`; решта source locks/recipes незмінні. Окремо погоджений 22.10.2026 виняток: тільки candidate host container замінений на digest `4a65616f389fa2a76955876a3e380284d3057cc04bfcac986008f20a710a0b76` після недоступності попереднього; baseline image не змінюється. Реальна перевірка інструментів/C++20 перед довгою компіляцією обов'язкова.
- Upstream-патч `4255130de410e0cbdab694b951085409d466b704`, SHA-256 `24c70218104aeae57ecf733b3ac6787314aaa8e7e1bf332f7bb4bec185ac4217`.
- Пул — три GPU-слоти; resize допускає лише одне додаткове покоління. Максимум texture 3840x2160, з DPR.
- Початковий вихід BGRA8 SDR із GPU tone mapping; HDR passthrough і всі Dolby Vision profiles не обіцяються.
- У GPU-шляху немає CPU Readback/RGBA IPC, WGL/ANGLE, приватного Electron IPC чи необмеженої черги.
- HTTP/HTTPS whitelist, main-frame/session ownership, async control queue та поведінка Lampa зберігаються.
- Жодних параметрів за назвою/URL/розміром фільму та серверного транскодування.
- Нові DLL/SDK/output/profile — окремі; чинний `build/libmpv-runtime.json` не замінюється під час прототипу.
- Push, tag, реліз, інсталяція WSL/Docker або використання VPS потребують окремого дозволу.
- Старі незакомічені performance-зміни зберігаємо; не включаємо сторонні untracked-файли у коміти.

## Review Focus

- Seek, resize і закриття між render та release: пізній кадр/ack не змінює нове покоління і не звільняє його текстуру (Tasks 2, 3, 6).
- Дві відеокарти або software/WARP fallback: реальний device і decoder відрізняються від очікуваних; це не називається GPU-успіхом (Tasks 2, 5, 7).
- Renderer crash або повільне GPU-release: UI/вихід не зависають, таймер не дає права писати у ще зайнятий ресурс (Tasks 2, 3, 6).
- Live IPTV, signed URLs, custom headers і відсутня duration: fallback не псує авторизацію й не виконує довільний seek (Tasks 6, 7).
- MPV-only тест швидкий, compositor повільний або кадри повторюються: callback FPS не підміняє унікальні видимі кадри/АВ-синхронність (Tasks 3, 5, 7).
