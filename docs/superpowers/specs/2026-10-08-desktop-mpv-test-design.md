# LampaUa Desktop: повна тестова portable-збірка з libmpv

## Мета і межі

Користувач погодив повну LampaUa Desktop у вигляді portable EXE для Windows
x64. Це звичайний інтерфейс LampaUa з каталогом, налаштуваннями та панеллю
відтворення Lampa, а не окремий застосунок для відкриття відеофайлів.

Попередній `lampaua-mpv-test` перевіряв тільки окремий рушій. Його результати
не доводять готовності інтеграції з Lampa й не замінюють цей артефакт.

Основний встановлений застосунок, його профіль і звичайні збірки не змінюються.
Не змінюємо Lampac, JackTor, VPS або `wwwroot/lampa-main`. Немає push, tag,
публікації релізу чи автоматичної доставки тестової версії.

## Вибір інтеграції

Рекомендований шлях: адаптер через штатний `Lampa.PlayerVideo.registerTube`.
Lampa зберігає власну панель керування, події та історію перегляду, а адаптер
надає сумісний об'єкт відео і виводить кадри libmpv у тому самому вікні.

Альтернатива: перехоплювати створення звичайного HTML video. Це сильніше
залежить від внутрішньої DOM-реалізації Lampa і ризикує зачепити інші відео.
Окреме вікно плеєра не підходить: користувач прямо відхилив окремий застосунок.

`verifyTube` у Lampa може примусово перемикати зовнішній запуск на внутрішній.
Тому реєстрація адаптера діє лише під час внутрішнього запуску, з урахуванням
явного `launch_player` і налаштувань поточного типу відтворення. Зовнішні
плеєри та YouTube залишаються на чинному шляху. Цю умову перевіряємо тестом.

## Компоненти і потік даних

- Ранній bootstrap тестового режиму встановлює окремий appId і userData ще
  до завантаження storeManager та отримання single-instance lock.
- Main-менеджер libmpv створює сервіс тільки у тестовій Windows x64 збірці,
  прив'язує його до головного BrowserWindow і завершує сесії до знищення вікна.
- Preload додає обмежений API libmpv, не змінюючи чинних Electron API та
  контрактів зовнішніх процесів.
- Локально зібраний renderer-код інжектується після готовності Lampa;
  залежності не завантажуються з CDN. Адаптер передає команди через preload
  та перетворює події libmpv на очікувані Lampa відеоподії.
- Native runtime використовує перевірений прототипом Electron 43.7.5 і
  закріплений electron-mpv-video commit
  `4944079b4133715848ea3c3bdaf99742b8c68406` з локальними виправленнями.
  Джерела, ліцензії, патчі та SHA256 DLL включаються в відтворюваний build flow.

Вбудований режим у новому тестовому профілі вибраний за замовчуванням.
Після цього збережений вибір користувача не переписується при перезапуску.
Адреси залишаються `https://kinohub.uk/` і `http://lampaua.mooo.com/`, з
HTTPS для нової адреси та HTTP для старої; ручного вводу адреси не додаємо.

## Контракт відтворення

Адаптер підтримує `src`, `load`, `play`, `pause`, `currentTime`, `duration`,
`paused`, `ended`, `videoWidth`, `videoHeight`, `volume`, `muted`,
`playbackRate`, `buffered`, відеоподії та ідемпотентне `destroy`.
Пауза, перемотування, гучність і швидкість керуються звичайною панеллю Lampa.
Події часу та завантаження надходять у PlayerVideo, щоб збереження і
відновлення позиції використовували наявний механізм Lampa.

Список аудіодоріжок і вбудованих субтитрів читається з libmpv; зміна вибору
через панель Lampa передається в libmpv. Розширення native API дозволяє тільки
визначені команди для цих функцій, без універсального виконання mpv-команд.
Субтитри відображаються в кадрі libmpv. Зовнішні субтитри від плагінів,
Chromecast, DRM і picture-in-picture не є критеріями цієї тестової збірки.

## Ізоляція, безпека та помилки

Тестовий профіль: `LampaUaDesktopMpvTest`, без копіювання або міграції
основного профілю. Звичайний autoUpdater і його ручні update-команди в
тестовому режимі недоступні: тестова програма не може встановити production
реліз поверх себе або зачепити встановлену програму.

TorrServer не запускається автоматично в новому тестовому профілі. Можна
підключити вже працюючий сервер через налаштування Lampa; застосунок не
завершує чужий процес TorrServer. Нові розширені IPC дозволені лише головному
frame прикріпленого вікна на одній із двох дозволених адрес Lampa.
Власник сесії перевіряється для кожної команди; навігація закриває старі сесії.
Медіаджерела для користувацького відтворення обмежуються HTTP/HTTPS, включно
з локальним TorrServer. Довільні файлові шляхи, mpv-конфігурації, скрипти та
команди не передаються з віддаленої сторінки у native runtime.

Створення, відкриття і закриття сесій серіалізуються, щоб швидкі повторні
запуски не використовували вже знищений native player. Помилка декодування
показується через штатний стан помилки Lampa; наступний запуск має працювати.
Native crash залишається ризиком експериментального рушія всередині Electron;
ізоляція декодера в окремий utility process не входить до цього прототипу.

## Збірка і критерії приймання

Скрипт створює ізольований staging повного застосунку з `src`, `assets`,
production-залежностями, native addon, `libmpv-2.dll`, Vulkan loader і
ліцензіями. Production package.json і звичайний release flow не змінюються.
Артефакт: `dist/mpv-desktop-test/lampaua-desktop-x64-1.5.24-mpv.2-portable.exe`.
Це тестовий EXE без інсталятора й без публікації; він не потребує Node, Git,
окремого mpv або інструментів розробника на машині користувача.

Перед передачею перевіряємо:

- Syntax checks, lint та чинні external-player і UA Player contract tests.
- Запуск саме повної LampaUa, каталог, налаштування і вибір обох адрес.
- Відтворення HTTP MP4/H264/AAC, MKV/AC3, MKV/EAC3 та AVI/Xvid/MP3 через
  справжній PlayerVideo flow, з рухомими непорожніми кадрами.
- Керування Lampa: пауза, перемотування, гучність, швидкість, аудіодоріжки,
  субтитри, збереження та відновлення позиції.
- Два послідовні запуски, помилка потоку і повторний запуск, навігація та
  закриття під час відтворення без залишених власних процесів.
- Відмови IPC для iframe, чужої сесії, забороненого джерела; відсутність
  автооновлення і змін основного профілю.
- Запуск упакованого portable EXE, контроль комплектності та SHA256.

Синтетичні HTTP тести не називаємо перевіркою реального TorrServer. Якщо
доступного тестового потоку TorrServer немає, це явно вказується при передачі
збірки разом з іншими неперевіреними сценаріями, без заяви про production-ready.
