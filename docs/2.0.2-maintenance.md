# Супровід LampaUa Desktop 2.0.2

## Межі сумісності

- Офіційний Electron 45.0.0 на всіх платформах; більше немає Windows ia32.
- macOS: мінімум 13.0.0 у пакеті; `minimumSystemVersion: 22.0.0` в метаданих
  оновлення означає Darwin 22, а не macOS 22. Старий electron-updater 6.8.9
  порівнює саме `os.release()` і має відхилити оновлення на Darwin 21/macOS 12.
- Windows 32-bit: старий updater може запропонувати x64-файл як запасний.
  Вимкнути це у вже встановленому клієнті дистанційно неможливо; користувачу
  потрібно вимкнути автооновлення. NSIS x64 перевіряє 64-бітну ОС до встановлення.
- Останній сумісний реліз Windows 32-bit/macOS 12 — 2.0.1. Не видаляти його файли.

## Компоненти

Актуальний Windows x64 runtime зафіксовано в
`build/electron-runtime-windows-x64.json`: SHA-256 офіційного ZIP із GitHub Electron
та окремі хеші executable, FFmpeg і Vulkan. `prepare-electron-runtime.ps1`
перевіряє архів; builder повторно перевіряє файли й компілює addon для Electron 45.
Попередній AC3/EAC3 manifest залишається для історичних збірок, але не для 2.0.2.
Власна перевірена libmpv DLL і комплект її джерел не змінені.

Мережеві зміни перенесено вибірково з ARST113/lampa-desktop:
`814ca4649c3f58f6d856221dd6726206bc2df58f` та
`14848478178427d550e9329af8b9a98a73306606`.
Використано Chromium `net.fetch`, скасування потоку та таймаут лише заголовків,
без обмеження тривалості перегляду. Наші HTTPS/HTTP адреси й сервер не змінено.

electron-store 12: повний знімок налаштувань береться через `.store`, а не
`.get()` без ключа. Нове кешування не вмикається. TypeScript 7 потребує нового
Yarn: 4.18.1 виправляє помилкове застосування старого PnP-патча до native compiler.
Node для розробки: 24.15+ в межах 24.x. Типи Node — гілка 24, не 26.

## Збірка й оновлення

1. `corepack yarn install --immutable`.
2. `corepack yarn build-win` — Windows x64 із MPV.
3. `corepack yarn build-win-arm64` — Windows ARM64 із браузерним рушієм.
4. `node scripts/merge-windows-updates.cjs` — лише x64/ARM64, з перевіркою SHA-512.
5. macOS: DMG для встановлення та ZIP для автооновлення, x64/ARM64.
6. Перед тегом виконати контракти, lint, native lifecycle та повний playback QA,
   включно з AC3/EAC3, браузерним DASH, IPTV, захищеними джерелами та 4К-керуванням.
7. Тег створює чернетку. Публікувати лише після перевірки отриманих CI-файлів,
   контрольних сум і метаданих автооновлення, як описано в release-maintenance.md.

Автотест повного додатка запускає GUI з `windowsHide: false`: прихований запуск
у цій Windows давав порожнє видиме вікно, хоча CDP отримував кольорові кадри.
У видимому запуску користувач підтвердив каталог і тестове відео. Не вважати
сам CDP-знімок доказом коректного показу на фізичному екрані.
